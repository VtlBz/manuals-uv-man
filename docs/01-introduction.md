# Раздел 1. Введение и мотивация

---

## Что такое uv

`uv` - это универсальный менеджер пакетов и проектов для Python, разработанный
компанией [Astral](https://astral.sh/) - авторами популярного линтера [Ruff](https://docs.astral.sh/ruff/).

Как и Ruff, `uv` написан на Rust, что обеспечивает высокую производительность.
По результатам бенчмарков `uv` работает в 10-100 раз быстрее, чем `pip`, при
выполнении типичных операций установки и разрешения зависимостей.

Проект активно развивается и уже используется в продакшн-проектах по всему миру.

Ключевая идея uv - **один инструмент вместо семи**. Вместо того чтобы
жонглировать `pip`, `pip-tools`, `pyenv`, `virtualenv`, `pipx`, `poetry` и `twine`,
вы получаете единый CLI, который покрывает все эти сценарии.

!!! note "Открытый исходный код"
    uv распространяется под лицензиями MIT и Apache 2.0.
    Исходный код доступен на [GitHub](https://github.com/astral-sh/uv).

## Когда uv - не лучший выбор

`uv` покрывает подавляющее большинство сценариев Python-разработки, но есть
ситуации, где он может быть не оптимальным выбором.

### Тяжелые научные зависимости

Если ваш проект активно использует пакеты, распространяемые через `conda`
(особенно с бинарными зависимостями, не представленными на PyPI), экосистема
Conda/Mamba может оставаться более удобным решением. Это касается, в частности:

- пакетов с привязкой к CUDA-версиям (некоторые сборки PyTorch, TensorFlow);
- библиотек, зависящих от системных C/Fortran-библиотек, недоступных через PyPI;
- окружений, где важна совместная установка
  Python и не-Python-пакетов (R, Julia).

!!! note "uv и научные пакеты"
    Большинство популярных научных пакетов (NumPy, pandas, scikit-learn,
    PyTorch) **прекрасно устанавливаются через uv**, так как они предоставляют
    wheel-пакеты на PyPI. Проблемы возникают только с пакетами, которые
    **доступны исключительно через conda-каналы**.

### Корпоративные ограничения

В некоторых организациях политики безопасности требуют использования
определенных инструментов, прошедших аудит. Если в вашей компании
стандартизирован другой менеджер пакетов, переход на `uv` потребует
согласования с командой безопасности.

### Стабильность API

`uv` находится в стадии активной разработки (версия 0.x). Хотя команда Astral
придерживается принципа обратной совместимости, отдельные флаги и поведение
могут меняться между минорными версиями. В критичных CI/CD-пайплайнах
рекомендуется фиксировать версию `uv`.

## Какие инструменты заменяет uv

Если вы работали с Python достаточно долго, у вас наверняка накопился целый
набор утилит для разных задач. `uv` объединяет их функциональность в одном инструменте.

### Таблица соответствия

| Задача | Старый инструмент | Эквивалент в uv |
| ------ | ----------------- | --------------- |
| Управление версиями Python | `pyenv install/local/global` | `uv python install/pin/list` |
| Создание виртуальных окружений | `python -m venv`, `virtualenv` | `uv venv` |
| Установка пакетов | `pip install` | `uv pip install`, `uv add` |
| Фиксация зависимостей | `pip-compile` (pip-tools) | `uv lock` |
| Синхронизация окружения | `pip-sync` (pip-tools) | `uv sync` |
| Запуск CLI-инструментов | `pipx run` | `uvx` / `uv tool run` |
| Управление проектом | `poetry init/add/lock/install` | `uv init`, `uv add`, `uv lock`, `uv sync` |
| Публикация пакетов | `twine upload` | `uv publish` |

### Что это означает на практике

Рассмотрим типичный рабочий процесс Python-разработчика до и после перехода на uv.

**До uv** - набор из 5+ инструментов:

```bash
# Установка и управление версиями Python
pyenv install 3.12.4
pyenv local 3.12.4

# Создание виртуального окружения
python -m venv .venv
source .venv/bin/activate

# Установка и фиксация зависимостей (два подхода):
# a) базовый - pip + freeze
pip install flask sqlalchemy
pip freeze > requirements.txt
# b) продвинутый - pip-tools (зависимости в requirements.in)
pip-compile requirements.in -o requirements.txt
pip-sync requirements.txt

# Запуск одноразовых инструментов
pipx run black .

# Публикация пакета
twine upload dist/*
```

**С uv** - один инструмент:

```bash
# Установка и фиксация версии Python
uv python install 3.12
uv python pin 3.12

# Инициализация проекта (создает pyproject.toml)
uv init

# Добавление зависимостей (обновляет pyproject.toml и uv.lock)
uv add flask sqlalchemy

# Синхронизация окружения по lockfile
uv sync

# Запуск одноразовых инструментов
uvx black .

# Публикация пакета
uv publish
```

!!! note "Виртуальное окружение создается автоматически"
    В отличие от классического подхода, вам не нужно вручную создавать
    `.venv`. Окружение создается автоматически при первой команде,
    которой оно необходимо (`uv add`, `uv sync`, `uv run`).

!!! tip "Постепенная миграция"
    Вам не нужно переходить на `uv` целиком за один день. Можно начать с
    использования `uv pip install` как замены обычного `pip` - это уже даст
    прирост скорости. Затем постепенно переводить проекты
    на `pyproject.toml` + `uv lock`.

## Ключевые преимущества uv

### 1. Скорость

`uv` написан на Rust и использует высоко оптимизированный
резолвер зависимостей. Реальные замеры показывают ускорение
в **10-100 раз** по сравнению с pip на типичных операциях.

Пример: установка зависимостей среднего Django-проекта (~50 пакетов),
по официальным замерам [Astral](https://github.com/astral-sh/uv):

| Инструмент | Время (холодный кеш) | Время (теплый кеш) |
| ---------- | -------------------- | ------------------ |
| pip | ~30 сек | ~12 сек |
| uv | ~2 сек | ~0.3 сек |

Скорость особенно заметна в CI/CD-пайплайнах, где каждая секунда сборки
имеет значение. Глобальный кеш с дедупликацией дополнительно экономит
дисковое пространство при работе с множеством проектов.

### 2. Единый инструмент

Вместо того чтобы помнить синтаксис семи разных утилит (`pip`, `pip-tools`,
`pyenv`, `virtualenv`, `pipx`, `poetry`, `twine`), достаточно выучить один CLI.
Это снижает когнитивную нагрузку, упрощает онбординг новых участников команды
и управление версиями Python (без отдельного `pyenv`).

### 3. Универсальный lockfile

В отличие от плоского `requirements.txt`, `uv.lock` - универсальный
кросс-платформенный файл с фиксацией всего графа зависимостей и хешей
по умолчанию.

```toml
# uv.lock - универсальный lockfile (кроссплатформенный, генерируется автоматически)
# Не редактируйте вручную

[[package]]
name = "flask"
version = "3.1.1"
source = { registry = "https://pypi.org/simple" }
...
```

!!! warning "Не редактируйте uv.lock вручную"
    Файл `uv.lock` генерируется автоматически командами `uv lock` и `uv add`.
    Ручное редактирование может привести к невалидному состоянию.

### 4. Для установки uv не нужен Python

`uv` - это самостоятельный бинарный файл. Его можно установить без
предустановленного Python, а затем через `uv` установить нужную версию Python.
Это решает классическую проблему "курицы и яйца" (чтобы поставить pip, нужен
Python, а чтобы управлять Python...). `uv` следует современным стандартам
экосистемы: PEP 621 (pyproject.toml), PEP 723 (inline-метаданные скриптов),
PEP 735 (группы зависимостей), PEP 508 (спецификации зависимостей).

## Архитектура uv: основные подсистемы

`uv` - не монолитная утилита, а набор логически связанных подсистем.
Понимание этой структуры поможет вам ориентироваться в командах.

### Обзор подсистем

```text
uv
├── python          # Управление версиями Python
│   ├── install     # Скачать и установить Python
│   ├── list        # Список доступных версий
│   ├── pin         # Привязать версию к проекту
│   ├── find        # Найти установленный Python
│   └── uninstall   # Удалить версию Python
│
├── Project         # Управление проектом (pyproject.toml + uv.lock)
│   ├── init        # Создать новый проект
│   ├── add         # Добавить зависимость
│   ├── remove      # Удалить зависимость
│   ├── lock        # Сгенерировать/обновить lockfile
│   ├── sync        # Синхронизировать окружение с lockfile
│   ├── run         # Запустить команду в окружении проекта
│   ├── tree        # Показать дерево зависимостей
│   └── export      # Экспорт в requirements.txt
│
├── tool            # Управление глобальными инструментами
│   ├── run (uvx)   # Запуск инструмента без установки
│   ├── install     # Глобальная установка инструмента
│   ├── list        # Список установленных инструментов
│   └── uninstall   # Удаление инструмента
│
├── pip             # pip-совместимый интерфейс
│   ├── install     # Установка пакетов
│   ├── uninstall   # Удаление пакетов
│   ├── compile     # Компиляция requirements
│   ├── sync        # Синхронизация из файла requirements
│   ├── list        # Список установленных пакетов
│   ├── freeze      # Вывод установленных пакетов
│   └── show        # Информация о пакете
│
├── venv            # Создание виртуального окружения
│
├── build / publish # Сборка и публикация пакетов
│
├── cache           # Управление кешем
│   ├── clean       # Очистить кеш
│   ├── prune       # Удалить неиспользуемые записи
│   └── dir         # Показать путь к кешу
│
└── self            # Самообновление
    └── update      # Обновить uv
```

### Группы команд

Команды `uv` можно разделить на несколько категорий по назначению:

**Управление проектами** - полный цикл работы с проектом: инициализация,
зависимости, lockfile, синхронизация, виртуальные окружения. Это центральная
часть `uv`, подробно рассматривается в разделах
[Инициализация проекта](04-project-init.md),
[Зависимости](06-dependencies.md),
[Окружения](05-environments.md),
[Sync-workflow](07-sync-workflow.md).

**Выполнение скриптов и инструментов** - запуск кода в контексте проекта
(`uv run`), запуск одноразовых CLI-инструментов (`uvx`).
Подробнее - в разделе [Запуск кода и инструментов](08-running-code.md).

**Управление версиями Python** - установка, переключение, привязка версий
интерпретатора к проектам.
Подробнее - в разделе [Управление версиями Python](03-python-versions.md).

**pip-совместимый интерфейс** - привычные команды для тех, кто мигрирует с pip.
Полезны в переходный период и в CI-скриптах.
Подробнее - в разделе [Миграция](12-migration.md).

**Служебные команды** - управление кешем, самообновление,
сборка и публикация пакетов. Рассматривается в разделах
[Управление кешем](09-configuration.md#управление-кешем),
[Обновление uv](02-installation.md#обновление-uv),
[Сборка и публикация](11-publishing.md).
