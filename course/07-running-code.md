## Вопросы для самопроверки

??? question "Что делает uv run перед выполнением команды?"
    `uv run` автоматически проверяет наличие виртуального окружения (создает
    его, если нужно) и синхронизирует зависимости с lockfile (`uv sync`). Только
    после этого запускается указанная команда. Этот шаг можно пропустить флагом
    `--no-sync`.

??? question "Что такое PEP 723 и как uv его использует?"
    PEP 723 определяет формат для указания метаданных (зависимости, версия
    Python) непосредственно в Python-скрипте через специальный блок комментариев
    `# /// script`. При вызове `uv run script.py` uv читает этот блок, создает
    временное окружение, устанавливает указанные зависимости и запускает скрипт.
    Это позволяет создавать полностью автономные скрипты - один файл содержит и
    код, и его зависимости.

??? question "В чем разница между uvx ruff и uv tool install ruff?"
    `uvx ruff` (сокращение для `uv tool run ruff`) создает временное окружение,
    устанавливает ruff и запускает его. Окружение кешируется, но ruff не
    добавляется в PATH.

    `uv tool install ruff` устанавливает ruff в постоянное изолированное
    окружение и добавляет исполняемый файл в `~/.local/bin/`, делая команду
    `ruff` доступной из любого каталога без использования `uvx`.

??? question "Как загрузить переменные окружения из файла при запуске через uv run?"
    Используйте флаг `--env-file`:

    ```bash
    uv run --env-file .env python app.py
    ```

    Можно указать несколько файлов (последующие перезаписывают предыдущие):

    ```bash
    uv run --env-file .env --env-file .env.local python app.py
    ```

    Или настройте через переменную `UV_ENV_FILE=.env`, чтобы не указывать флаг
    каждый раз.

??? question "Можно ли запустить uvx с конкретной версией Python?"
    Да. Используйте флаг `--python`:

    ```bash
    uvx --python 3.12 jupyter notebook
    ```

    Это полезно, когда инструмент требует определенной версии Python или когда
    нужно проверить совместимость.
