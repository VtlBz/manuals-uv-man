# Курсовые материалы: 10-docker-ci.md

!!! info "Цели модуля"
    После прохождения этого модуля вы будете:

    - эффективно применять uv в Docker-образах;
    - настраивать CI/CD-пайплайны с uv;
    - знать pip-совместимый интерфейс uv и случаи его применения.

---

## Практическое задание

### Задание 1: Dockerfile с uv

Напишите Dockerfile для простого FastAPI-приложения:

1. Используйте multi-stage build.
2. Примените оптимизацию слоев (сначала зависимости, потом код).
3. Установите `UV_PYTHON_DOWNLOADS=never` и `UV_COMPILE_BYTECODE=1`.
4. Запускайте приложение от непривилегированного пользователя.

### Задание 2: GitHub Actions workflow

Напишите `.github/workflows/ci.yml`, который:

1. Устанавливает uv через `astral-sh/setup-uv@v4`.
2. Запускает `uv sync --locked`.
3. Запускает тесты через `uv run pytest`.
4. Тестирует на Python 3.11, 3.12 и 3.13 (matrix strategy).

## Контрольные вопросы

??? question "Что делает `UV_PYTHON_DOWNLOADS=never` в Docker?"
    Запрещает uv скачивать собственную копию Python. Вместо этого uv будет
    использовать Python, уже установленный в контейнере (из базового образа
    `python:3.12-slim`). Это уменьшает размер образа и время сборки.

??? question "Зачем использовать `--locked` в CI/CD?"
    Флаг `--locked` заставляет uv проверить, что `uv.lock` соответствует
    `pyproject.toml`. Если lockfile устарел, команда завершится ошибкой вместо
    молчаливого обновления зависимостей. Это гарантирует воспроизводимость
    сборки.

??? question "Когда стоит использовать `uv pip install` вместо `uv add`?"
    `uv pip install` полезен для legacy-проектов с `requirements.txt`, при
    постепенной миграции на uv, для одноразовых скриптов, и в CI/CD-пайплайнах,
    которые пока не переведены на проектный workflow uv. В новых проектах
    предпочтительнее использовать `uv add`.
