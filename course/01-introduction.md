# Курсовые материалы: 01-introduction.md

!!! info "Цели модуля"
    После прохождения этого модуля вы будете:

    - понимать, что такое uv и кто его разрабатывает;
    - знать, какие существующие инструменты uv заменяет;
    - понимать ключевые преимущества uv перед классическим набором утилит;
    - ориентироваться в архитектуре и основных подсистемах uv;
    - осознанно принимать решение о переходе на uv в своих проектах.

---

## Практическое задание

!!! example "Задание"
    Выполните следующие шаги, чтобы познакомиться с uv на практике.

    **Шаг 1.** Проверьте, установлен ли uv в вашей системе:

    ```bash
    uv version
    ```

    Если uv не найден - не беда. В [следующем модуле](02-installation.md) мы
    разберем установку. Пока просто запомните, какие инструменты из таблицы
    соответствия вы используете сейчас.

    **Шаг 2.** Если uv установлен, изучите справку:

    ```bash
    uv help
    ```

    Обратите внимание на группы команд в выводе. Соотнесите их со схемой
    подсистем из раздела "Архитектура".

    **Шаг 3.** Посмотрите справку по конкретной подкоманде:

    ```bash
    uv help python
    uv help init
    ```

    **Шаг 4.** Составьте для себя список инструментов, которые вы используете
    сейчас, из таблицы соответствия в начале модуля. Запишите, какие команды uv
    их заменяют. Это будет вашей личной картой миграции.

## Контрольные вопросы

??? question "На каком языке программирования написан uv?"
    uv написан на **Rust**. Это обеспечивает высокую скорость работы (в 10-100
    раз быстрее pip) и отсутствие зависимости от
    установленного Python для самого инструмента.

??? question "Назовите три инструмента, которые заменяет uv"
    uv заменяет множество инструментов. Вот некоторые из них:

    - **pip** - установка пакетов (`uv pip install`, `uv add`)
    - **pip-tools** - фиксация зависимостей (`uv lock`, `uv sync`)
    - **pyenv** - управление версиями Python (`uv python install/pin`)
    - **virtualenv / venv** - виртуальные окружения (`uv venv`)
    - **pipx** - запуск CLI-инструментов (`uvx`)
    - **Poetry** - управление проектом (`uv init`, `uv add`, `uv lock`)
    - **twine** - публикация пакетов (`uv publish`)

??? question "Какой файл является основным конфигурационным файлом uv-проекта?"
    Основной конфигурационный файл - **`pyproject.toml`**. Он соответствует
    стандарту PEP 621 и содержит метаданные проекта, список зависимостей и
    настройки инструментов. uv также поддерживает секцию
    `[tool.uv]` для специфичных настроек.

??? question "Для чего нужен файл uv.lock?"
    **`uv.lock`** - это lockfile, который фиксирует точные версии всех
    зависимостей проекта (включая транзитивные). Он обеспечивает:

    - **воспроизводимость** - одинаковые версии пакетов на всех машинах;
    - **кроссплатформенность** - один файл для Linux, macOS и Windows;
    - **безопасность** - хеши пакетов для проверки целостности.

    Файл генерируется автоматически командами `uv lock` и `uv add`. Его нужно
    коммитить в систему контроля версий.

??? question "В каких случаях uv может быть не лучшим выбором?"
    uv может быть не оптимальным выбором в следующих случаях:

    - проект зависит от пакетов, доступных **только через
      conda-каналы** (не через PyPI);
    - корпоративная политика безопасности требует
      использования аудированных инструментов;
    - нужна абсолютная стабильность CLI-интерфейса (uv пока в версии 0.x).
