# Курсовые материалы: 15-best-practices.md

!!! info "Цели модуля"
    После прохождения этого модуля вы будете:

    - знать рекомендуемую структуру проекта с uv;
    - иметь набор командных соглашений для работы в команде;
    - быстро находить нужную команду в шпаргалке;
    - уметь сопоставлять привычные инструменты с эквивалентами uv;
    - решать типичные проблемы, возникающие при работе с uv.

---

## Практическое задание

Завершающее задание объединяет знания из всех модулей:

1. **Создайте новый проект** с `uv init`, добавьте 2-3 зависимости и
   dev-зависимости.
2. **Настройте `.gitignore`** по рекомендациям из этого модуля.
3. **Напишите `.github/workflows/ci.yml`** с тестированием на нескольких версиях
   Python.
4. **Напишите Dockerfile** с multi-stage build и оптимизацией слоев.
5. **Проверьте**, что `uv sync --locked` работает корректно после каждого
   изменения зависимостей.

---

??? question "Вопросы для самопроверки"

    **1. Нужно ли коммитить uv.lock в git? Почему?**

    Да, обязательно. `uv.lock` фиксирует точные версии всех зависимостей
    (включая транзитивные). Без него каждый разработчик и CI-сервер может
    получить разные версии зависимостей, что приводит к ошибкам вида "у меня
    работает, а у тебя нет".

    ---

    **2. Как рекомендуется запускать тесты в CI?**

    Через `uv run pytest` после `uv sync --locked`. Флаг `--locked` гарантирует,
    что lockfile актуален, а `uv run` автоматически использует правильное
    виртуальное окружение без ручной активации.

    ---

    **3. Как узнать, какой пакет зависит от конкретной транзитивной
    зависимости?**

    С помощью команды `uv tree --invert package-name`. Флаг `--invert`
    показывает обратное дерево зависимостей: от указанного пакета вверх к тем,
    кто от него зависит.

    ---

    **4. Назовите эквивалент `pip-compile` в uv.**

    Есть два варианта: `uv pip compile requirements.in` (pip-совместимый
    интерфейс, прямая замена) и `uv lock` (проектный workflow, работает с
    `pyproject.toml` вместо `requirements.in`).

    ---

    **5. Какой python-preference рекомендуется для командной работы?**

    `python-preference = "managed"`. Эта настройка заставляет uv использовать
    собственные управляемые версии Python, а не системные. Это гарантирует, что
    все участники команды работают с одинаковой сборкой Python, независимо от
    того, что установлено в их системе.
