## Контрольные вопросы

??? question "Как сохранить точные версии пакетов при миграции с pip-tools?"
    Используйте флаг `-c` (constraint) при импорте зависимостей:

    ```bash
    uv add -r requirements.in -c requirements.txt
    ```

    Здесь `requirements.in` содержит список пакетов (с мягкими спецификаторами),
    а `requirements.txt` - точные зафиксированные версии. uv использует версии
    из constraint-файла при разрешении зависимостей, гарантируя что `uv.lock`
    зафиксирует те же версии.

??? question "Какие секции pyproject.toml нужно добавить для работы с uv?"
    Для полноценной работы с uv нужны следующие секции:

    - **`[project]`** - метаданные проекта и список production-зависимостей
      (обязательно);
    - **`[dependency-groups]`** - группы зависимостей (dev, test, docs и т.д.);
    - **`[tool.uv]`** - настройки, специфичные для uv (опционально).

    Существующие секции (`[tool.ruff]`, `[tool.mypy]` и т.д.) остаются
    нетронутыми.

??? question "Какой подход рекомендуется для постепенной миграции с pyenv?"
    Рекомендуется четырёхфазный подход:

    1. **Фаза 1** - оставить pyenv для Python, перейти на uv для пакетов
       (`python-preference = "system"`);
    2. **Фаза 2** - начать устанавливать Python через uv параллельно с pyenv;
    3. **Фаза 3** - полностью перейти на uv для управления Python
       (`python-preference = "managed"`);
    4. **Фаза 4** - удалить pyenv (опционально).

    Каждая фаза может длиться столько, сколько нужно. Нет необходимости
    форсировать переход.

??? question "Что делает команда `uv add -r requirements.in -c requirements.txt`?"
    Эта команда:

    1. Читает список пакетов из `requirements.in` (файл с "мягкими"
       зависимостями);
    2. Добавляет их в `[project.dependencies]` в `pyproject.toml`;
    3. При разрешении зависимостей использует `requirements.txt` как constraint
       - ограничивает версии теми, что указаны в этом файле;
    4. Генерирует `uv.lock` с зафиксированными версиями.

    Результат: в `pyproject.toml` записываются мягкие спецификаторы (например,
    `flask>=3.1`), а в `uv.lock` - точные версии из constraint-файла (например,
    `flask==3.1.1`).

??? question "Когда лучше использовать `uvx migrate-to-uv`, а когда - ручную миграцию?"
    **Автоматическая миграция** (`uvx migrate-to-uv`) подходит для:

    - стандартных проектов с типичной структурой;
    - миграции с Poetry или Pipenv (сложная конвертация метаданных);
    - массовой миграции нескольких проектов.

    **Ручная миграция** предпочтительна, когда:

    - нужно сохранить точные версии из lockfile (через `-c` constraint);
    - проект имеет нестандартную структуру зависимостей;
    - вы хотите полный контроль над тем, что попадет в `pyproject.toml`.
