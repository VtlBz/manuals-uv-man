## Вопросы для самопроверки

??? question "В чем разница между managed и system Python в uv?"
    **Managed Python** - это версии, установленные самим uv через
    `uv python install`. Они хранятся в `~/.local/share/uv/python/`
    (Linux/macOS) и полностью управляются uv.

    **System Python** - это все остальные интерпретаторы: установленные ОС,
    pyenv, Homebrew, собранные из исходников и т.д. uv может их
    использовать, но не управляет ими.

    Ключевой момент: Python, установленный через pyenv, является
    **system** Python с точки зрения uv.

??? question "Что делает `python-preference = \"only-managed\"`?"
    Этот параметр заставляет uv использовать **исключительно** managed Python
    (установленный через `uv python install`). Все системные интерпретаторы
    игнорируются, даже если они подходят по версии.
    Эквивалент флага `--managed-python`.

    Если managed-версия не найдена и автоматические загрузки включены, uv
    скачает нужную версию. Если загрузки отключены - uv выдаст ошибку.

??? question "Как uv обрабатывает файлы `.python-version`, созданные pyenv-virtualenv?"
    Плагин pyenv-virtualenv записывает в `.python-version` имя виртуального
    окружения (например, `my-project-env`), а не номер версии Python. Начиная с
    версии 0.6, uv **игнорирует** такие записи, так как они не являются
    валидными спецификациями версии. uv просто пропускает этот файл и продолжает
    поиск интерпретатора по стандартному алгоритму обнаружения.

??? question "Где хранятся managed-версии Python, установленные через uv?"
    По умолчанию:

    - **Linux/macOS**: `~/.local/share/uv/python/`
    - **Windows**: `%APPDATA%\uv\data\python\`

    Путь можно переопределить переменной окружения `UV_PYTHON_INSTALL_DIR`.
    Узнать текущий путь: `uv python dir`.

??? question "Что произойдет, если `requires-python` в `pyproject.toml` конфликтует с `.python-version`?"
    uv выдаст ошибку. Например, если `.python-version` указывает `3.10`, а
    `requires-python` задает `>=3.12`, uv не сможет выполнить команду, потому
    что запрашиваемая версия (3.10) не
    удовлетворяет требованию проекта (>=3.12).

    Решение: обновить `.python-version` до версии, совместимой с
    `requires-python`, выполнив `uv python pin 3.12`.
