## Практическое задание

!!! example "Задание: Работа с виртуальными окружениями"

    1. **Создайте новый проект и понаблюдайте за автоматическим созданием
       .venv:**

        ```bash
        uv init env-lab
        cd env-lab
        ls -la .venv  # should not exist yet
        uv sync
        ls -la .venv  # now it exists
        ```

    2. **Настройте ваш IDE:**

        - Откройте проект `env-lab` в VSCode/Cursor или PyCharm.
        - Убедитесь, что IDE обнаружил интерпретатор из `.venv`.
        - Если нет - настройте вручную по инструкции из раздела выше.
        - Откройте встроенный терминал и проверьте `which python`.

    3. **Сравните uv run и ручную активацию:**

        Создайте файл `app.py`:

        ```python

        print(f"Python: {sys.executable}")
        ```

## Вопросы для самопроверки

??? question "Когда uv автоматически создает .venv?"
    При первом выполнении `uv sync` или `uv run` в каталоге проекта, если
    `.venv` еще не существует. Версия Python определяется из файла
    `.python-version` или поля `requires-python` в `pyproject.toml`.

??? question "Нужно ли активировать .venv для использования uv run?"
    Нет. Команда `uv run` самостоятельно находит и использует окружение `.venv`
    в каталоге проекта. Активация не требуется - uv подставляет правильный
    интерпретатор и окружение автоматически.

??? question "Как настроить VSCode/Cursor для использования интерпретатора из .venv?"
    В большинстве случаев VSCode/Cursor обнаруживает `.venv` автоматически. Если
    этого не произошло, добавьте в `.vscode/settings.json`:

    ```json
    {
        "python.defaultInterpreterPath": "${workspaceFolder}/.venv/bin/python"
    }
    ```

    Или воспользуйтесь Command Palette: ++ctrl+shift+p++ ->
    `Python: Select Interpreter`.

??? question "Для чего используется UV_PROJECT_ENVIRONMENT?"
    Переменная `UV_PROJECT_ENVIRONMENT` позволяет изменить путь, по которому uv
    создает виртуальное окружение проекта. По умолчанию это `.venv` в корне
    проекта. Это полезно для размещения окружения вне дерева проекта или для
    общих окружений между связанными проектами.

??? question "Нужно ли коммитить .venv в git?"
    Нет. Директория `.venv` содержит бинарные файлы интерпретатора и
    установленные пакеты, которые специфичны для текущей ОС и архитектуры. Она
    должна быть в `.gitignore`. При выполнении `uv init` файл `.gitignore` с
    записью `.venv/` создается автоматически. Все зависимости воспроизводятся из
    `uv.lock`.
